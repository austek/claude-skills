# Swap SipHash for ahash/FxHash When Keys Aren't Attacker-Controlled [MEDIUM]

## Description
`std::collections::HashMap` defaults to SipHash-1-3 specifically because it resists hash-flooding: an attacker who can choose keys can't force every key into the same bucket and degrade lookups to O(n). That resistance costs roughly 2-4x the CPU of a non-cryptographic hasher on typical integer or short-string keys, and for a map keyed by something the outside world never touches — an internal ID, a handle generated by the program itself — that cost buys nothing. `ahash::AHashMap` is a drop-in swap that keeps a randomized per-process seed (so it's still DoS-resistant, just faster); `rustc_hash::FxHashMap` goes further and drops randomization entirely for maximum speed, which makes it appropriate only for keys the program fully controls.

## Bad Example
```rust
use std::collections::HashMap;

// Handles are generated internally — SipHash's DoS resistance is paying for
// a threat that doesn't exist in this map's key space.
fn build_handle_table(handles: &[(u32, Resource)]) -> HashMap<u32, Resource> {
    handles.iter().cloned().collect()
}
```

## Good Example
```rust
// ahash: safe general-purpose upgrade, still DoS-resistant.
use ahash::AHashMap;

fn build_handle_table(handles: &[(u32, Resource)]) -> AHashMap<u32, Resource> {
    handles.iter().cloned().collect()
}

// FxHashMap: fastest option, but the hash is predictable — only ever use it
// for keys the program generates itself (compiler internals, node IDs).
use rustc_hash::FxHashMap;

fn build_node_index(nodes: &[(u32, NodeData)]) -> FxHashMap<u32, NodeData> {
    nodes.iter().cloned().collect()
}
```

## Notes
- Never route externally-supplied keys (user input, request paths, file names from untrusted sources) through `FxHashMap` or any non-randomized hasher — doing so turns a performance optimization into a denial-of-service vulnerability.
- Confirm map operations actually show up in a profile before swapping hashers — see `perf-profile-first`; on a map that isn't in the hot path, the change adds a dependency for no measurable benefit.
- `with_capacity` (or `with_capacity_and_hasher` for a non-default hasher) still matters regardless of which hasher is chosen — pre-sizing avoids rehashing on growth independently of hash speed.
